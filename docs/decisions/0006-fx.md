# 0006 — fx (visual effects) — secondary

Status: exploring · 2026-10-14

**Secondary to everything else.** Nothing in core, react, testing or theme waits
on fx, and fx work does not start before the core's first wave ships.

## What it is

A separate collection of visual components that exist *for* how they look: an AI
orb that reacts to an agent's state and audio level, auroras, waveforms, shader
effects. It is the shareable showcase that brings people to rind-ui (and to
Reado).

## What we agreed so far

- **Not a theme of core.** The theme styles core's components; fx is a different
  kind of component. Some fx pieces have no headless counterpart at all (a
  background aurora); some sit on a core primitive (the Orb renders
  `AgentPresence` from `core/ai`).
- **Distributed as a shadcn registry** (`npx shadcn add <site>/r/agent-orb`), not an
  npm package: people want to edit the shader, and we avoid breaking changes.
- **Light WebGL**: WebGL2 directly or a tiny library such as ogl — not three.js.
- **Rules for every effect**: `prefers-reduced-motion`, a non-WebGL fallback, pause
  when off-screen, lazy loading, SSR-safe.

## Open questions

- **"Creating effects without creating them."** The wish is to not hand-author each
  effect, which is a paradox to resolve: procedural/parametric effects generated
  from a small set of parameters? A shader graph? To be explored.
- **Configurators.** The website could let users configure a component (colours,
  speed, intensity, shape) and take away a ready-to-use result — code via the
  registry, or a config object. Plausibly the answer to the question above:
  effects defined by parameters, tuned in a configurator rather than written by
  hand.
